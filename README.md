# remnawave-node-deployer

Сервис для автоматического подключения новых нод к панели
[Remnawave](https://github.com/remnawave/panel). Управление идёт через
Telegram-бота или веб-интерфейс: вы указываете доступ к серверу, а сервис сам
настраивает его и регистрирует как ноду в панели.

Вся ручная рутина (заход по SSH, базовая защита сервера, установка Docker,
разворот контейнера `remnanode`, регистрация в панели и проверка статуса)
выполняется автоматически в фоне.

## Возможности

- Подключение сервера по SSH: деплойер ставит свой ключ для беспарольной
  работы. Парольный вход на сервере не трогает, жёсткий hardening доступа
  остаётся за владельцем.
- Базовый hardening сервера: UFW и fail2ban.
- Установка Docker и разворот контейнера `remnanode` через Ansible.
- Регистрация ноды в панели Remnawave по API и ожидание статуса `online`.
- Выбор способа доступа к серверу: логин с паролем (деплойер сам поставит ключ)
  или собственный публичный ключ.
- Подключение к уже существующей панели или разворот новой с нуля (разворот с
  нуля пока за флагом, обкатывается).
- Фоновый мониторинг: бот сам опрашивает статус нод и шлёт алерт, когда нода
  уходит в офлайн.
- Управление нодой из бота по SSH: перезапуск контейнера и перезагрузка сервера.
- Синхронизация уже заведённых в панели нод и удочерение импортированных
  (выдача им SSH-доступа, после чего ими можно управлять).
- Лог-ротация и лимит памяти у контейнера ноды, чтобы логи не забивали диск, а
  утечка памяти не валила весь сервер.
- Управление через бота на кнопках: меню, мастер добавления ноды, список нод со
  статусом и удалением, привязка панели. Команды набирать не нужно.
- Хранение SSH-ключей и токенов панели в HashiCorp Vault; секреты, привязанная
  панель и список нод переживают перезапуск.
- Аудит действий, выполненных на сервере.

## Установка и запуск

```bash
git clone https://github.com/krumzeze/remnawave-node-deployer.git
cd remnawave-node-deployer
cp .env.example .env     # заполнить настройки
docker compose up -d
```

Поднимаются сервисы: бот, воркер, веб-интерфейс, PostgreSQL, Redis и Vault.

## Конфигурация

Настройки задаются через `.env` (шаблон в `.env.example`):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `ADMIN_TELEGRAM_IDS` | ID админов через запятую (не барьер доступа) |
| `POSTGRES_*` | подключение к PostgreSQL |
| `REDIS_*` | подключение к Redis |
| `VAULT_ADDR`, `VAULT_TOKEN` | доступ к Vault |
| `WEB_HOST`, `WEB_PORT` | адрес веб-интерфейса |
| `WEB_BASE_URL`, `WEB_SECRET` | базовый URL дашборда и секрет подписи ссылок |

Панель Remnawave каждый пользователь подключает свою прямо в боте — её URL и
токен хранятся отдельно на каждого пользователя, глобальной панели в `.env` нет.

## Статус

Многопользовательский: доступ открытый, каждый подключает свою панель и
обслуживает свои ноды, данные пользователей разделены. Бесплатный тариф - одна
нода и один конфиг на ноду; больше - по подписке (Telegram Stars). Основной
сценарий (добавить ноду к существующей панели и обслуживать её из бота)
работает. Разворот панели с нуля пока скрыт за флагом и обкатывается.
