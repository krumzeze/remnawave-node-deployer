# remnawave-node-deployer

Telegram-бот и бэкенд, которые из обычного VPS делают рабочую ноду
[Remnawave](https://github.com/remnawave/panel) без ручной возни с SSH и
Docker. Даёшь серверу доступ — дальше всё происходит само: бот заходит по SSH,
выкладывает свой ключ и переводит сервер на ключевую авторизацию, ставит Docker,
поднимает контейнер `remnanode`, регистрирует ноду в панели через API и ждёт,
пока она перейдёт в `online`.

Изначально это учебный проект, чтобы закрыть на практике стек DevOps/DevSecOps:
конфиг-менеджмент чужих машин, фоновая оркестрация долгих задач, работа с
секретами и нормальная модель угроз для сервиса, который получает root на
N серверах.

## Как это устроено

```
Telegram-бот ─┐
веб-дашборд  ─┤  кладут задачу
              ▼
        Redis + arq  ──▶  воркер
                           ├─ SSH bootstrap (asyncssh)
                           ├─ Ansible: hardening + Docker
                           ├─ разворот remnanode (compose)
                           └─ опрос API панели до online
панель Remnawave ◀── CreateNode / статус
Vault            ◀── SSH-ключи и токены панелей (зашифрованы на диске)
Postgres         ◀── ноды, панели, задачи, аудит — пароли тут не лежат никогда
```

Жизненный цикл задачи:
`queued → bootstrapping → provisioning → registering → online`, а при сбое —
`failed` или `rolled_back`.

## Что уже решено

Поддерживаем два сценария: развернуть панель с нуля и подключить уже
существующую — в боте они равноправны. Целевая версия панели — `2.7.x`.

Способ доступа к серверу выбирает пользователь: либо логин с паролем (бот сам
переведёт на ключ), либо свой публичный ключ через one-liner. Пароль живёт
ровно одну операцию, в базу и логи не попадает. Парольный вход отключается
только после того, как вход по ключу реально проверен — чтобы не остаться без
доступа к чужому серверу.

## Стек

aiogram, asyncssh, ansible-runner, Remnawave Python SDK `2.7.x`, Redis + arq,
HashiCorp Vault, PostgreSQL. В MVP поддерживается только Ubuntu 22.04 и 24.04.

## Запуск (dev)

```bash
cp .env.example .env        # вписать токены и доступы
docker compose up -d        # bot, worker, redis, postgres, vault
```
